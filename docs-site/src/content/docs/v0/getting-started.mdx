This is the five-minute path. Pick the tab that matches how you work. Each
one is end-to-end: install, send a report, and confirm it landed.

There are **two milestones**:

1. **Send a report** against our live demo doc and watch it land as a public
   GitHub Issue. This proves the protocol path works end-to-end — it takes a
   minute and needs no setup on your side.
2. **Receive reports as GitHub Issues** on your own repo. This needs a
   one-time Hub setup (connect the GitHub App, verify your domain). It's
   covered at the end and links to the [Hub guide](/v0/hub/).

<Aside type="caution" title="These examples file a real, public Issue">
The examples below report against
[`demo-libraryx.com/payments`](https://demo-libraryx.com/payments), a live
demo doc. Its domain is already verified, so your report doesn't just return a
`201` — it opens a **public** GitHub Issue at
[`fyd-demo-maintainer/demo-libraryx`](https://github.com/fyd-demo-maintainer/demo-libraryx/issues).
That demo exists for exactly this, so go ahead and run one — just tweak the
`summary` so the Hub doesn't de-duplicate it against an identical report
that's already on file.
</Aside>

<Tabs syncKey="audience">

<TabItem label="Python">

<Steps>

1. **Install the SDK.**

   ```sh
   pip install fixyourdocs
   ```

   Requires Python 3.9+.

2. **Send your first report.**

   ```python
   from fixyourdocs import Client, Report

   report = Report.create(
       doc_url="https://demo-libraryx.com/payments",
       summary="The payments guide still shows the v1 charge flow; the API now needs a PaymentIntent.",
       kind="outdated",
       agent_name="my-agent",
   )

   with Client(api_url="https://hub.fixyourdocs.io") as client:
       result = client.send(report)

   print(result.id, result.is_duplicate)
   ```

   A successful call prints a report `id` (a ULID). That's the Hub
   confirming it accepted your report (`201 Created`).

   Prefer the command line? The same thing without writing code:

   ```sh
   pipx run fixyourdocs report \
     --doc-url https://demo-libraryx.com/payments \
     --summary "The payments guide still shows the v1 charge flow; the API now needs a PaymentIntent." \
     --agent my-agent \
     --kind outdated
   ```

</Steps>

</TabItem>

<TabItem label="TypeScript">

<Steps>

1. **Install the SDK.**

   ```sh
   npm install @fixyourdocs/sdk
   ```

   Requires Node.js 20+ (the SDK uses the built-in global `fetch`; no
   runtime dependencies).

2. **Send your first report.**

   ```ts
   import { Client, buildReport } from "@fixyourdocs/sdk";

   const client = new Client({ apiUrl: "https://hub.fixyourdocs.io" });

   const report = buildReport({
     docUrl: "https://demo-libraryx.com/payments",
     summary: "The payments guide still shows the v1 charge flow; the API now needs a PaymentIntent.",
     kind: "outdated",
     agentName: "my-agent",
   });

   const result = await client.send(report);
   console.log(result.id, result.isDuplicate ? "(duplicate)" : "(new)");
   ```

   A successful call logs a report `id` (a ULID) — the Hub confirming it
   accepted your report (`201 Created`).

   No code? The CLI ships with the SDK:

   ```sh
   npx @fixyourdocs/sdk report \
     --doc-url https://demo-libraryx.com/payments \
     --summary "The payments guide still shows the v1 charge flow; the API now needs a PaymentIntent." \
     --agent my-agent \
     --kind outdated
   ```

</Steps>

</TabItem>

<TabItem label="Agent">

You're wiring an AI coding agent so it files reports on its own when it
hits broken docs. There's nothing to install on the agent side — pick the
path that matches your client.

<Steps>

1. **Drop the AGENTS.md block into your repo.**

   ```sh
   npx @fixyourdocs/sdk init
   ```

   This appends the canonical [Docs Feedback Protocol](/v0/protocol/) block
   to your `AGENTS.md` (or `CLAUDE.md`, `.cursor/rules`, or
   `.github/copilot-instructions.md`). Any agent that reads that file now
   knows how to file a report. See the [AGENTS.md snippet](/v0/agents-md/)
   page for what the block contains.

2. **Or add the MCP server** for MCP-aware clients (Claude Desktop, Cursor,
   Codex). Add this to your client's MCP config:

   ```jsonc
   {
     "mcpServers": {
       "fixyourdocs": {
         "command": "npx",
         "args": ["-y", "@fixyourdocs/mcp-server"]
       }
     }
   }
   ```

   The agent gets one tool, `file_doc_feedback`. Full per-client config is
   on the [MCP server](/v0/mcp/) page.

   <Aside type="tip">
   Two adoption modes: paste the snippet into a **repo** (Mode A) so agents
   report *that* repo's docs, or install the MCP server into your **own,
   global** client config (Mode B) so your agent offers — with your OK, on
   public docs only — to report the **third-party** docs it consults. See
   [Reporting third-party docs](/v0/mcp/#reporting-third-party-docs-consumer-side--mode-b).
   </Aside>

3. **Confirm the path works** by sending a report by hand — the exact call
   the agent will make:

   ```sh
   curl -X POST https://hub.fixyourdocs.io/v1/reports \
     -H 'Content-Type: application/json' \
     -d '{
       "protocol_version": "0",
       "doc_url": "https://demo-libraryx.com/payments",
       "agent":   { "name": "claude-code" },
       "report":  {
         "kind":    "outdated",
         "summary": "The payments guide still shows the v1 charge flow; the API now needs a PaymentIntent."
       }
     }'
   ```

   You get back `{ "id": "...", ... }` with HTTP `201` — the Hub accepted it.

</Steps>

</TabItem>

## Make reports show up as GitHub Issues — on your repo

The report you just sent forwarded to a public Issue because
**`demo-libraryx.com` is a verified demo domain**. Your own docs aren't
verified yet, so a report against *them* would get a `201` and be
de-duplicated, but **not** forwarded. The Hub only forwards a report when the
report's `doc_url` host matches a domain **you have verified you own** and
bound to a GitHub integration — that's what keeps anyone from filing issues
against a repo that isn't theirs.

<Aside type="caution" title="Forwarding requires a verified domain">
The demo forwarded because its domain is verified. A report against a domain
nobody has verified is accepted and de-duplicated, but it is **not**
forwarded — no Issue is created. To close the loop on your own docs, connect
your repo and verify your domain. This is a one-time setup.
</Aside>

The one-time setup, in three moves:

<Steps>

1. **Sign in** at [fixyourdocs.io](https://fixyourdocs.io) and install the
   **FixYourDocs GitHub App** on the repo that should receive issues.

2. **Verify the domain** your docs live on by adding a single DNS `TXT`
   record the Hub gives you.

3. **Point the integration** at your repo and an Issue body template.

</Steps>

The [Hub guide](/v0/hub/) walks through each call and the exact DNS record.
Once it's done, the next report against a doc on your verified domain shows
up at `https://github.com/<your-org>/<your-repo>/issues`.
